# 开发说明

## 结构

```
main.py            入口：优先用 pywebview 打开 webui/；没装时退回旧的 CustomTkinter 界面（--tk 强制旧界面）
devserver.py       开发用：在浏览器里打开界面，后端是真的 Api
webui/             界面：index.html、app.css、ink.js（纸和墨的几何与纹理）、app.js（界面逻辑）
core/
  api.py           界面和后端之间唯一的接口，不依赖 pywebview，可以直接测试
  safety.py        什么不能动：系统、程序数据、个人文件夹本身、OneDrive、链接；可清理缓存的名单
  recycle.py       唯一真正把文件移到回收站的地方（先确认能进回收站）
  cleaner.py       删除流程：preflight（只读预检）→ execute（逐项再查一次后移到回收站）
  mover.py         移动流程：plan_moves → execute_moves → undo，每一批都能撤销
  scanner.py       大文件扫描（只读）
  space.py         空间分类统计（只读）
  inspect.py       “看看里面”的建议（只读）
  dupes.py         重复文件（只读）
  tidy.py          整理下载和桌面的建议（只读）
  cleanables.py    可放心清理的项目
  oplog.py         每一项操作的记录（JSON Lines）
  prefs.py         用户说过“留着”的文件
ui/                旧的 CustomTkinter 界面，作为备用
tests/             pytest
```

## 规则

- 只有 `recycle.py` 能把文件移到回收站，只有 `mover.py` 能移动文件。其他地方禁止调用 `os.remove`、`shutil.rmtree`、`send2trash` 等，测试会检查。`mover.py` 里删除只允许出现在三个函数里（删掉已核对的原件、清掉自己没复制完的临时副本、撤销后删掉自己建的空文件夹）。
- 所有动文件的操作都分两步：只读的预检 → 用户确认 → 执行时逐项再查一次。
- 扫描、建议、重复文件、整理建议都是只读的。
- 界面只调用 `Api`，从不直接动文件。耗时的事都在后台线程，界面轮询 `state()`。
- 判断“很久没用”只看修改时间，不看访问时间。
- 新增受保护的位置或可清理的缓存，只改 `safety.py`。

详细的规则和原因见 [安全与流程](安全与流程.md)。

## 测试

```bash
pip install pytest
```

```bash
python -m pytest tests
```

全部测试都在临时文件夹里进行，回收站用假的代替。`test_safety_flow.py` 一条安全规则一个测试；`test_mover.py` 是移动和撤销；`test_api.py`、`test_api_organize.py` 是完整流程。

## 在浏览器里调界面

```bash
python devserver.py
```

然后打开 <http://127.0.0.1:8765>。后端是真的，会真的移动文件——请把 `HOME` / `USERPROFILE` 指向一个测试用的文件夹再启动。

## 视觉

- 只有纸和墨，没有彩色。颜色、字号都在 `webui/app.css` 开头；字号只用五档。
- 墨色按大小分五级；可用空间是纸，所有文字写在纸上。
- 文字说人话：说“为什么”，不说路径和扩展名；后果在确认时说。
