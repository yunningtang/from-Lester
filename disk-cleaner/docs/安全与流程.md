# 安全与流程

这份文档说明清理时每一步做什么、为什么这样做。改删除相关的代码前先读一遍。

## 一次清理的完整流程

```
扫描（只读）
  │  记下每个文件的大小和修改时间（指纹）
  ▼
用户勾选
  │  缓存类默认选上；你的文件、旧安装包、微信缓存默认不选
  ▼
预检 preflight（只读，后台线程）
  │  每一项过一遍安全规则 → 能移 / 不能移（附原因）
  │  文件和扫描时比有没有变
  │  这个盘有没有回收站、回收站开没开、放不放得下
  │  回收站会不会被挤满
  ▼
确认（界面）
  │  告诉用户：移走什么、共多大、哪些不会动以及原因、
  │  “移到回收站后空间还不会变多，清空回收站后才会”
  ▼
执行 execute（后台线程）
  │  每一项移动前**再查一遍**全部规则（防止确认之后又有变化）
  │  移到回收站，确认文件确实离开了原处
  │  一项失败不影响其他项；每一项都写日志
  ▼
结果
     已移到回收站多少；没移动的有哪些、为什么；可以去回收站找回
```

## 每一层防什么

| 风险 | 怎么防 | 代码 |
|---|---|---|
| 文件放不进回收站，Windows 直接永久删除（send2trash 的默认行为） | 只在本地固定磁盘上删；回收站关掉了不删；比回收站容量大的不删；调用系统时带 FOF_WANTNUKEWARNING，万一要永久删会先问 | `core/recycle.py` |
| 删到系统文件 | Windows、Program Files、ProgramData、页面文件等一律不碰 | `safety.is_hard_protected` |
| 删到程序数据 | AppData 只允许名单里的缓存目录 | `safety.SAFE_CACHES` |
| 把整个“文档”“下载”或 C:\Users 删掉 | 这些文件夹本身和它们的上级不能删 | `safety.is_keep_root` |
| 删 OneDrive 文件，云端和其他电脑上的也跟着没了 | OneDrive 里的一律不删；“仅在线”的占位文件不算占用 | `safety.is_in_cloud`、`fs.is_cloud_placeholder` |
| TEMP 环境变量被改成主目录，“清临时文件”清掉一大片 | 缓存目录必须像缓存目录：不是根目录、不是主目录、不是重要文件夹的上级；临时文件夹必须叫 Temp | `safety._sane_cache_root` |
| 便携程序（直接在下载里运行的 exe）被当成安装包 | 只认 setup/install/installer 名字的 exe 和 msi；默认不选 | `SAFE_CACHES` 的 installers |
| 通过链接或目录联接删到别处 | 链接本身不删、不跟随；字面路径和真实路径都要通过检查 | `safety.is_link`、`_lex`/`_norm` |
| 扫描后文件被换掉或改了 | 删除前比较大小和修改时间，变了就不删 | `cleaner._changed` |
| 缓存扫描后又被程序用上 | 删除前重新核对名字和时间条件 | `cleanables.still_matches` |
| 同时选了文件夹和它里面的文件 | 只移最上层那个 | `cleaner._dedupe` |
| 写日志失败导致清理停在一半 | 日志写不进去就先留在内存里，清理继续 | `OpLog.write` |
| 一个文件被占用，后面的都没删 | 每一项单独处理，失败的记下原因 | `cleaner.execute` |
| 界面说“已释放 21 G”，其实空间没变 | 一律说“已移到回收站”，并说明清空回收站后才腾出空间 | `ui/confirm.py` |
| 硬链接文件（删一个不腾空间） | 大文件列表里标出来 | `scanner.FileEntry.hardlinked` |

## 还没有做、需要在 Windows 上确认的

这些在 Linux 测试环境里测不到，第一次在 Windows 上运行时要专门试：

1. **回收站检查**：用一个 U 盘、一个比回收站容量大的文件、一个关掉回收站的盘各试一次，确认都被拒绝、文件还在。
2. **SHFileOperationW 调用**：确认普通文件进了回收站、能从回收站还原；被占用的文件报错而不是卡住。
3. **注册表读回收站容量**：`HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\BitBucket\Volume\{GUID}` 在有些电脑上没有，这时按磁盘的 5% 估算。
4. **OneDrive 占位文件**：确认“仅在线”的文件不出现在大文件列表里。
5. **长路径**（超过 260 个字符）：确认报错清楚，不会误删。
6. **性能**：临时文件夹里几万个文件时，预检和执行的时间。现在是一个一个移，必要时改成分批。
7. **pywebview 窗口**：无边框窗口能拖动（标题栏空白处）、最小化 / 最大化 / 关闭按钮有效、高分屏下字清楚。
8. **新加的缓存位置**：微信缓存（`文档\WeChat Files\*\FileStorage\Cache`、`文档\xwechat_files\*\cache`）、经典版 Teams、VS Code、缩略图缓存，在真实电脑上确认路径存在、清理后对应软件正常。
9. **藏得深的大块**：iPhone 备份、WSL / Docker 虚拟磁盘、Steam 的路径在真实电脑上能找到；页面文件和休眠文件的大小能读到。
10. **重复文件**：两份一样的文件，只有一份被建议移走；“全部移走”后另一份确实还在。
11. **跨盘移动**：往 D 盘挪一个几 GB 的视频，确认复制完以后原件才消失；中途拔掉移动硬盘，原件完好、不留半个文件。
12. **撤销**：整理下载后撤销，所有文件回到原处、“归档”文件夹消失；往归档里放一个自己的文件后再撤销，这个文件和文件夹都还在。

## “看看里面”的建议从哪来（core/inspect.py）

| 建议 | 怎么判断 |
|---|---|
| 能重新生成 | 文件夹叫 node_modules、.next、__pycache__ 等；build / dist / target 只在旁边有 package.json、pyproject.toml 等项目文件时才算 |
| 一模一样 | 大小相同 → 开头和结尾 1 MB 相同 → 完整 SHA-256 相同。留最早的那份，留下的那份绝不建议移走；同时选了两份也只移一份 |
| 安装包、系统镜像 | 名字里有 setup / install 的 exe、msi；iso / img |
| 已经解压过 | 压缩包旁边有同名文件夹 |
| 很久没用 | 下载、微信、QQ 里一年以上没打开或修改的 |
| 你的文件 | 视频、图片、文档、代码项目里的大文件，只说明，不建议删 |
| 已经在“可放心清理”里的 | 不再重复建议，也不重复计算 |

## 移动和撤销（core/mover.py）

整理、挪到别的盘、撤销都走这里，和删除一样分两步：只读的 `plan_moves` → 确认 → `execute_moves` 逐项再查一次。

| 风险 | 怎么防 |
|---|---|
| 跨盘复制到一半断电或出错 | 先复制到带 `.liubai-part` 后缀的临时名字，边复制边算哈希，复制完再完整读一遍比对；一致了才改成正式名字，最后才删原来那份。任何一步出错，原件不动，临时副本清掉 |
| 覆盖目标位置已有的文件 | 同名时自动改成“名字 (2)”；执行前再查一次目标不存在 |
| 把文件挪进系统目录、程序目录或 OneDrive | 目标位置同样过安全检查，不合适就拒绝 |
| 目标盘被塞满 | 跨盘时按每个盘累计大小，至少给目标盘留 1 G |
| 挪到网络盘，断网就打不开 | 不往网络盘挪；移动硬盘会提醒“拔掉就看不到了” |
| 文件夹挪进它自己里面 | 拒绝 |
| 撤销时覆盖了新文件 | 原位置已经有文件的那一项不放回 |
| 撤销后留下一堆空的“归档”文件夹 | 记下每一批新建的文件夹，撤销后只删其中已经空了的 |
| 同一批撤销两次 | 记录里标记已撤销，不能再撤 |

“很久没用”只看修改时间：访问时间在 Windows 上常常不记录，而且找重复文件时读一遍就会把它刷新。

## 对界面（留白）的影响

- 清理以后**纸不会马上变大**。移走的墨流进“回收站”那一块；用户自己清空回收站后，纸才变大。
- 结果提示写“已移到回收站 21 G。清空回收站后，这些空间才会空出来”，并给一个“打开回收站”的入口（打开 Windows 自己的回收站，留白不替用户清空）。
- 确认框里列出“不会动”的项和原因，不只是能移的。
